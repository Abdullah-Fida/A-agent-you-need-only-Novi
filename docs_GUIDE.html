01What this system is

One repository, three deployed pieces, six modules. You control all of it by talking to an orb.

What one news story produces

        ┌──────────────► Telegram channel   post + branded image
        │
News ───┼──────────────► Website article    800-1200 words, full SEO
story   │
        ├──────────────► Facebook           via Buffer, links the article
        ├──────────────► X / Twitter        optional, off by default
        └──────────────► Reddit             optional

The website article is written first, so its URL can be linked from the Facebook caption. Each destination is isolated — one failing never stops the others.

Everything starts OFF. After deploying, nothing posts until you switch modules on from the dashboard. That is deliberate — it lets you verify the connections before anything goes public.

02Where to host each piece

All three live in the same GitHub repo. Each host points at a different folder using its Root Directory setting.

Render · Web Service

The bot (backend)

Python. Runs the scheduler, Telegram clients, AI and the HTTP API. Must run continuously.

Root: / (repo root)
Start: python main.py
Vercel · Project 1

NOVI dashboard

React + Three.js voice interface. Static — talks to the Render backend over HTTPS.

Root: novi-dashboard
Output: dist
Vercel · Project 2

News website

Next.js. Reads articles straight from Supabase, so it needs no backend.

Root: website

Render's free tier sleeps after ~15 minutes of no traffic. The bot pings itself every 4 minutes to stay awake, but that only works if RENDER_EXTERNAL_URL is set to your public URL. Without it the ping goes to localhost and Render still idles you — the most common cause of "it randomly stops working".

Why Resend and not Gmail: Render's free tier blocks outbound SMTP ports. Gmail works locally and then silently sends nothing in production. Resend uses HTTPS, so it works. Configure both — Gmail is the automatic fallback.

Use a second phone number for the stealth account. It scrapes and messages strangers; if Telegram flags it you lose that number, not your main account.

04Setup, step by step

About 30–45 minutes end to end.

  1. Create the database

    Supabase → SQL Editor → paste all of database/schema.sql → Run. The last statement returns 8 rows; that is your confirmation.

  2. Generate Telegram session strings

    Sessions are how the bot logs in without a code every time. Run twice — once per account:

    python tools/stealth_login.py send main      # your number
python tools/stealth_login.py code 12345

python tools/stealth_login.py send stealth   # the burner
python tools/stealth_login.py code 12345

    Each prints a long string and writes it into .env.

  3. Find your group IDs

    python tools/list_groups.py prints every chat the account can see, with IDs. You need the Whale Tracker group and the invite group.

    Supergroup IDs need a -100 prefix. -5533411583 will not resolve; -1005533411583 will. This one detail silently disables all group posting.

  4. Connect Facebook to Buffer

    In Buffer, connect your Facebook page, then create an API token. The bot discovers the page automatically.

  5. Deploy the backend to Render

    New Web Service → connect the repo → Root / → Build pip install -r requirements.txt → Start python main.py. Add every variable from section 05, then deploy.

  6. Deploy the two Vercel projects

    Import the same repo twice. Set Root Directory to novi-dashboard for one and website for the other. Only the website needs environment variables.

  7. Link them together

    Set SITE_URL on Render to the website's Vercel URL, so Facebook captions link to your articles.

  8. Verify, then switch on

    Open /api/health — every module should report connected. Then enable modules from the dashboard one at a time and watch your inbox.

Vercel — the dashboard

None. It finds the backend on its own and the Groq key lives server-side. VITE_API_BASE can still override the backend URL if you ever need it.

Never put an API key in a VITE_ or NEXT_PUBLIC_ variable unless it is meant to be public. Those are compiled into the JavaScript bundle and readable by anyone who opens the site. The Supabase anon key is designed for this; a Groq or OpenRouter key is not.

06Daily operation

All times Pakistan Standard Time (UTC+5).

  1. 00:00Asleep — no posts, replies or invites
  2. 00:40Post slot
  3. 01:00Asleep until 07:00
  4. 08:00Morning brief — digest of the top 5 stories
  5. 10:30Post slot
  6. 13:00Post slot
  7. 13:40Post slot
  8. 16:00Post slot
  9. 19:30Post slot
  10. 21:00Evening wrap
  11. 23:00Sleep begins

What happens at a post slot

slot opens → wait 0-10 min random jitter (never posts on an exact minute)
           → scrape 21 RSS feeds, score and cluster stories
           → AI writes Telegram + tweet + Reddit versions
           → generate branded image
           → publish to Telegram
           → write website article  (if the website module is on)
           → cross-post to Facebook, X, Reddit
           → email you a confirmation

Each slot stays open 25 minutes — longer than the maximum jitter, so a post can never miss its own window. Every slot fires at most once per day.

Background loops

LoopEveryPurpose
Keep-alive ping4 minStops Render idling the instance
Heartbeat5 minChecks every Telegram client and auto-reconnects dead ones
Stealth invite cycle1 hourOne scrape + invite pass, if all safety gates allow
Metric ingest3 hoursRecords subscriber count, updates growth stats
Main tick60 secChecks whether a post slot is due

Sleep window

Default 23:00 → 07:00. While asleep: no posts, no replies, no invites. The bot stays connected and the API keeps answering. Change it live:

  • “Novi, sleep from 1am to 6am”
  • “Novi, never sleep” → 24/7
  • “Novi, are you sleeping?” → reports live state

07The modules

News Agent

Scrapes 21 RSS feeds, scores by relevance, clusters related stories, writes the post and image, publishes to Telegram.

default off

Signal Copier

Watches crypto channels, strips the competitor's branding with AI, posts the cleansed signal into your group. Duplicates ignored.

on when connected

Stealth Marketer

Two modes: helpful replies in competitor groups, and opt-in invitations sent by DM.

default off

Website / Auto-Blogging

800–1200 word article per story with full SEO. While off the writer never runs, so its API key is never charged.

default off

Fan-out

Cross-posts to Reddit, X and Facebook. Each isolated — one failing never stops the rest.

with news agent

Growth Engine

Measures whether any of it gains subscribers, attributes growth to actions, recommends what to change.

always measuring

Relevance scoring

South-Asia keywords +10, crypto +8, general interest +3. Stories cluster when titles overlap >40%, so the AI reads 2–3 perspectives before writing. Highest-scoring cluster wins.

SEO shipped with every article

  • Canonical URL, OpenGraph and Twitter cards
  • NewsArticle + BreadcrumbList JSON-LD
  • AI-written meta title, description and keywords
  • Automatic entry in /sitemap.xml and /feed.xml
  • Anything under 250 words is rejected rather than published

Failover: every call retries at least 3× with exponential backoff. On a 404 it walks a fallback model list; on 429/401 it rotates API keys. Only then does it give up and email you.

Switching any task to another model

MODEL_ARTICLE=deepseek/deepseek-r1
MODEL_SEO=openai/gpt-4o-mini

Avoid reasoning models for structured output. A reasoning model narrates its thinking before answering. The SEO prompt once asked for “meta_title (≤60 chars)” and the model spent its entire token budget counting letters, so no JSON ever arrived. Length limits are now enforced in code and the parser recovers from both reasoning preambles and truncated replies — but a plain instruct model is still the safer choice here.

Change any of them live: “Novi, increase posts to 10”.

The invite cap is enforced in code at 30/day. Ask for more and NOVI applies 30 and tells you it capped it. Telegram bans burner numbers that invite aggressively, so this ceiling is not adjustable from the dashboard.

Emergency lockAfter auto-kill, reactivation is blocked until you manually reset

One session string, one IP. Telegram permanently revokes an authorization key used from two IP addresses at once. Never run the bot locally while Render is running the same session — suspend the Render service first.

The bot verifies the schema at startup and names any missing table in the log, rather than discarding writes silently.

RLS must allow the anon role. The bot connects with the Supabase anon key. A policy requiring authenticated or service_role rejects every insert with no visible error.

Key hygiene

  • Never commit .env — it is gitignored, keep it that way
  • Rotate any key that has been pasted into a chat, email or screenshot
  • Telegram session strings are full account access; treat them like passwords
  • To revoke a leaked session: Telegram → Settings → Devices → Terminate All Other Sessions
