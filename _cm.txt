Find the Pinterest board the way Buffer actually exposes it

A live end-to-end run got as far as publishing and was refused with
"Pinterest posts require a board to be selected". Buffer's schema marks
boardServiceId optional; the API enforces it.

find_board was guessing at channel.boards and channel.pinterestBoards, neither
of which exists. Boards hang off the channel's metadata union:

  channel(input: {id}) { metadata { ... on PinterestMetadata { boards { id name } } } }

publish() now resolves and caches a board before building the request, and
says what is wrong when it cannot.

Verified against the live account: the query works, and the board list comes
back empty because the Pinterest account has no boards yet. That is the
remaining blocker and it is fixed on Pinterest, not here.

Everything before that step is confirmed working end to end against the real
account: Buffer connected, channel found, copy written, a 195 KB branded pin
built from the real product photo, image hosted publicly, compliance passed.

Also stopped the upload failure message naming article-images when a
different bucket was asked for, which sent me looking in the wrong place.
